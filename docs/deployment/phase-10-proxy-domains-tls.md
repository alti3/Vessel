# Phase 10: Reverse Proxy, Domains, TLS, and Routing

Phase 10 adds the first routing layer for deployed applications.

## Coolify Reference

The upstream Coolify default branch was inspected for proxy and domain behavior before implementation:

- `app/Actions/Proxy/GetProxyConfiguration.php`
- `app/Actions/Proxy/SaveProxyConfiguration.php`
- `app/Actions/Proxy/StartProxy.php`
- application `fqdn` handling in API, Livewire, and model code
- SSL certificate migrations and notification templates
- Coolify docs for domains, Traefik ACME, wildcard certificates, and dynamic proxy configuration

Vessel keeps the important product semantics: application domains are managed by the control plane, proxy configuration is generated deterministically, validation blocks unsafe config, apply/reload is auditable and protected by a lock, previous config is retained for rollback, and normal app TLS starts with Traefik ACME.

## Provider Choice

The MVP provider is Traefik.

Rationale:

- Coolify defaults to Traefik for automatic app routing and ACME.
- Traefik dynamic file configuration lets Vessel generate per-server route documents without editing application containers.
- The provider boundary keeps Caddy, Nginx, and custom providers possible later.

## Architecture

- `Vessel.Application.Proxy.IProxyProvider` generates and validates the dynamic (routes) document per server (`ValidateRoutes`, `Generate`, `Validate`).
- `Vessel.Infrastructure.Proxy.TraefikProxyProvider` implements it with typed YAML (YamlDotNet).
- `ProxyLifecycleService` (Application) owns the per-server proxy lifecycle: settings, static configuration delivery, start/stop/restart, status, deployment-time network attachment, and dynamic configuration delivery. It implements `IProxyStatusProbe` for health polling.
- `IProxyRuntimeRenderer` → `TraefikRuntimeRenderer` (Infrastructure) renders the static `traefik.yml` and the proxy `docker-compose.yml` with YamlDotNet.
- `IProxyContainerRuntime` → `DockerProxyContainerRuntime` (Infrastructure) drives the Docker/Podman CLI on the server's runtime host.
- `IServerFileChannel` (Application, `Servers/Files`) delivers files to a server's runtime host: `LocalServerFileChannel` for `Local`/`DockerSocket` servers and `SshServerFileChannel` for `Ssh` servers. Both are atomic (temporary file in the destination directory, final mode applied, rename) and accept only validated relative paths.
- `ServerCommandExecutor` (Infrastructure, `Servers`) runs structured argument vectors locally through `IProcessRunner` or remotely through `ISshClient` with every argument POSIX-quoted. SSH host and user are validated so neither can be read as an `ssh` option.
- `ComponentVersions` (Application, `Common`) is the single manifest of pinned runtime images. Traefik is pinned to `traefik:v3.7.16` (upstream Coolify `upstream.json`, `v3.7` latest patch).
- `ProxyConfigurationService` owns version records (encrypted at rest), validation, apply, restore-as-new-version, history retention, user dynamic configuration files, and audit. It runs under the same `proxy:{serverId}` lock as the lifecycle service.
- `ProxyRouteProjector` projects every routable resource on a server (applications, open previews, service-template resources) into `ProxyRoute`s that target a `RoutableEndpoint` (owner kind, upstream alias, internal port, Compose service).
- `DomainRoutingService` (applications) and `ServiceDomainService` (service-template resources) own route commands: `RouteAddress` parsing, save-time conflict checks (`DomainConflicts`), and route policies (`RoutePolicyWriter`).
- `CertificateInventoryService` mirrors Traefik's `acme.json` into `Certificate` rows and owns delete / delete-unused / backup restore. `ITraefikAcmeStore` → `TraefikAcmeStore` (Infrastructure) reads and edits `acme.json` over the server file channel.
- `CertificateManagementService` owns application-facing certificate listing and issuance requests.
- `CertificateIssuanceJob`, `CertificateSyncJob`, and `ProxyConfigurationHistoryCleanupJob` are thin Hangfire entry points that delegate back to Application services.
- Web controllers and Blazor pages call Application services only.

## Proxy Lifecycle

Upstream reference: `bootstrap/helpers/proxy.php` (`generateDefaultProxyConfiguration`, `connectProxyToNetworks`), `app/Actions/Proxy/{StartProxy,StopProxy,CheckProxy}.php`, `app/Enums/ProxyTypes.php`, `upstream.json`.

Each server gets one managed proxy container, `vessel-proxy` (compose project `vessel-proxy`). Files live under the server file root:

| Server connection | Root | Configure with |
| --- | --- | --- |
| `Local`, `DockerSocket` | `{AppContext.BaseDirectory}/storage/server-files` by default; host-native installs should use `/var/lib/vessel` | `Vessel:ServerFiles:LocalRootDirectory` |
| `Ssh` | `/var/lib/vessel` | `Vessel:ServerFiles:RemoteRootDirectory` |

```text
proxy/traefik.yml                 0644  static configuration
proxy/docker-compose.yml          0644  proxy compose file
proxy/dynamic/                    0755  file-provider directory (mounted read-only)
proxy/dynamic/vessel-routes.yml   0600  generated routes
proxy/acme/                       0700  ACME storage directory
proxy/acme/acme.json              0600  created only when missing; never overwritten
```

The static configuration:

- defines entrypoints `web` (`:80`) and `websecure` (`:443`);
- enables `ping` on `web`, which is used by the container healthcheck `traefik healthcheck --ping`;
- uses the file provider on `/etc/traefik/dynamic` with `watch: true`;
- defines the `letsencrypt` resolver (HTTP-01 on `web`, storage `/etc/traefik/acme/acme.json`);
- turns off version checks and anonymous usage reporting;
- has no `api` section, so the API and dashboard stay off.

Unlike upstream, the proxy has no Docker provider and does not mount `/var/run/docker.sock`. Routes come only from Vessel's file provider. Host ports come from the settings (default 80/443). HTTP-01 needs public port 80 to reach the `web` entrypoint.

Operations (all audited, all under the `proxy:{serverId}` lock):

- **Start** re-pins the image from `ComponentVersions` and writes the static files. Each file is read back and verified, except `acme.json`, which is create-only. Start then ensures the server network exists and runs `docker compose up --detach --remove-orphans --wait`. It fails if the container is not running afterwards.
- **Restart** does the same with `--force-recreate`.
- **Stop** stops and removes the container and records desired state `Stopped`. While stopped, deployments do not restart the proxy.
- **Status** comes from `docker container inspect` on the server's runtime. A missing, exited, `starting`, or `unhealthy` container is reported as not healthy. The status also shows `restartRequired` when the static configuration or the pinned image changed since the last start, and `imageOutdated` when the stored image differs from the manifest.
- **Proxy type None** turns off the managed proxy. Deployments skip proxy attachment and route generation. A manual apply or rollback is rejected. Changing the proxy type requires the proxy to be stopped first. `Caddy` is reserved and rejected.

Dynamic configuration is delivered by write-then-verify. The routes document is written atomically into `proxy/dynamic/` and read back, and the hash is recorded. Traefik reloads it through the file provider watch; there is no `SIGHUP`. Watch only sees atomic renames through the directory bind mount, which is why the directory is mounted rather than single files. If delivery or verification fails, the version is marked failed and the previous applied version is delivered again. If the proxy container is not running, the routes are still delivered, and the apply message and health report say the proxy is down.

During a deployment, after the server network exists and before application containers start, the runner calls `EnsureForDeploymentAsync`. It starts the proxy if it is missing and the desired state is `Running`, then runs `docker network connect` (idempotent). A failure is written to the deployment log as `stderr` and does not fail the deployment, matching upstream's `ignore_errors`.

Server health polling sets `ProxyHealthy` from the real container (`IProxyStatusProbe`) instead of from the proxy configuration history. A server with proxy type None reports `ProxyHealthy = true` because no proxy is expected.

SSH servers: file delivery and proxy commands run over OpenSSH through `IProcessRunner` with `StrictHostKeyChecking=yes`. The host key must already be known, and the user defaults to `root`. There is no per-server key reference yet (SRV-02/SEC-12), so the daemon user's SSH identity is used. Application deployments to SSH servers still fail closed in the runner.

API (`servers.read` for GET, `servers.write` for everything else):

```text
GET   /api/v1/servers/{id}/proxy
PATCH /api/v1/servers/{id}/proxy            { "proxyType": "Traefik|None", "httpPort": 80, "httpsPort": 443 }
POST  /api/v1/servers/{id}/proxy/start
POST  /api/v1/servers/{id}/proxy/stop
POST  /api/v1/servers/{id}/proxy/restart
```

## Domains and Route Identity (NET-03)

Upstream reference: `bootstrap/helpers/domains.php`, `app/Support/DomainUrlParts.php`, `fqdnLabelsForTraefik()`.

A route is a `RouteAddress` (Domain value object):

- scheme `http`/`https`; `ws`/`wss` are normalized to `http`/`https`. A scheme in the input sets TLS; without one the request's `tlsEnabled` applies.
- host kinds: DNS names (at least two labels; `_` allowed; IDN input converted to punycode; punycode TLDs such as `xn--p1ai`), wildcard `*.example.com` (covers exactly one label, rendered as Traefik `HostRegexp`), IPv4, and IPv6 (stored and matched without brackets). Single-label names are rejected. TLS is rejected for IP hosts.
- an optional path prefix, case preserved, routed as `PathPrefix(...)`. Paths may not contain empty, `.` or `..` segments, quotes, backticks or whitespace.
- a port in the input (`https://app.example.com:3000`) is the internal target port; public URLs stay portless.

The routing identity is host + path; the scheme is ignored, so the `http` and `https` forms of a domain are the same route. Identity is checked at save time across every application, open preview and service-template resource on every server (`DomainConflicts`). A conflict fails the save with the owner's name, or "a resource in another team" for other tenants. `forceDomainOverride: true` saves anyway and writes a `domain_route.conflict_overridden` audit record. Two claimants of the same identity on one server are still both quarantined at apply time, so an override never lets one resource silently take another's traffic.

`application_domains` keys on `(ApplicationId, DomainName, PathPrefix)`. The `DomainName` column holds the normalized host, and an index on `(DomainName, PathPrefix)` serves conflict lookups. The application create API applies the same parser and conflict check.

```text
GET    /api/v1/applications/{id}/domains
PUT    /api/v1/applications/{id}/domains                 { "host": "https://app.example.com/api", "targetPort": 3000, "tlsEnabled": true, "canonical": false, "redirectToCanonical": false, "policy": { ... }, "forceDomainOverride": false }
PUT    /api/v1/applications/{id}/domains/{host}          (host-only form, kept for compatibility)
DELETE /api/v1/applications/{id}/domains?address=https://app.example.com/api
DELETE /api/v1/applications/{id}/domains/{host}
GET    /api/v1/applications/{id}/domains/certificates
```

## Route Policies (NET-05)

Upstream reference: `fqdnLabelsForTraefik()`, `bootstrap/helpers/constants.php` (`TRAEFIK_GZIP_MIDDLEWARE`), `app/Enums/RedirectTypes.php`, `app/Traits/HasNoindexDomains.php`.

Each route has a `RoutePolicy` (stored as JSON; `{}` means the defaults):

| Field | Default | Effect |
| --- | --- | --- |
| `forceHttps` | `true` | TLS routes: the `http` router only redirects to HTTPS. When off, the `http` router serves the app with the same middlewares. |
| `redirectMode` | `Both` | `Www` redirects non-www hosts to `www.`, `NonWww` redirects `www.` hosts to the bare host (DNS hosts, not previews). |
| `permanentRedirect` | `false` | Redirects are temporary (302/307) unless enabled, because browsers cache 301s indefinitely. Applies to HTTPS, canonical and www redirects. |
| `compression` | `true` | `vessel-gzip-no-media-v1` compress middleware excluding `text/event-stream`, video, audio, images, archives and PDF (upstream `gzip-no-media` list). |
| `noIndex` | `false` | `X-Robots-Tag: noindex, nofollow` response header. |
| `stripPathPrefix` | `true` | Strips the route's path prefix before forwarding (upstream strip-prefix default). |
| `basicAuth` | off | Username plus a secret reference. The password is write-only: it is stored in the secret vault (`route-basic-auth:{hash}` key) and never returned or audited. At render time it is hashed with bcrypt cost 10 (`$2y$`) into the Traefik `basicAuth.users` line, with `removeHeader: true`. |

Middlewares are applied in a fixed order: redirects, basic auth, noindex, strip prefix, compression. Shared middleware names carry a version suffix so a definition change never conflicts with a stale one. The bcrypt salt is derived from the router key and credentials, so unchanged credentials render the same file (no new history version). A route whose basic-auth secret cannot be read is quarantined and never published without protection. The rendered file contains bcrypt hashes, which is one reason stored configuration text is encrypted (see history below).

## Routable Endpoints (NET-06)

Upstream reference: `app/Support/DomainPortOverrides.php`, `app/Livewire/Project/Service/Domains.php`, `app/Livewire/Project/Application/PreviewDomains.php`.

Every resource type projects into a `RoutableEndpoint`:

- **Application**: alias `vessel-app-{appId}`, port from the domain or the exposed port.
- **Preview**: alias `vessel-app-{appId}-pr-{n}`, host `{pr}.{domain}` from the canonical (or first) DNS domain. The preview keeps the source route's path, TLS and policy. Wildcard and IP domains cannot derive preview hosts.
- **Service-template resource**: each `service_domains` row names a Compose service and its internal port (the per-service port map). The alias is `vessel-svc-{serviceId}-{hash8(service)}`. Built-in templates with a known web endpoint (for example `pgadmin` → `pgadmin:80`) default the Compose service and port. When a service with domains is provisioned, the named Compose services join the external server network under their aliases (`IComposeDocumentBuilder.AttachServicesToNetwork`), the proxy is attached, and routes are applied after the stack starts. Routes added later are published by the next provision or a manual apply.

```text
GET    /api/v1/services/{id}/domains                      projects.read
PUT    /api/v1/services/{id}/domains                      projects.write  { "host": "https://pg.example.com", "composeService": "pgadmin", "targetPort": 80, "tlsEnabled": true, "policy": { ... } }
DELETE /api/v1/services/{id}/domains?address=...          projects.write
```

## Certificates from acme.json (NET-04)

Upstream reference: `app/Services/TraefikAcmeService.php`, `app/Actions/Proxy/{GetTraefikCertificates,DeleteTraefikCertificate,SaveTraefikAcmeFile,ListTraefikAcmeBackups,RestoreTraefikAcmeBackup,DeleteTraefikAcmeBackup}.php`.

Traefik issues and renews certificates itself. Vessel's `certificates` table is an inventory mirrored from `proxy/acme/acme.json`:

- **Sync**: the recurring `certificates.renew-due` job (the old renewal job id is reused so its stale definition is replaced) runs `CertificateSyncJob` every 30 minutes. For each reachable server with a managed proxy, under the proxy lock (busy servers are skipped), it parses each resolver's certificates (main domain, SANs, `NotBefore`/`NotAfter` of the leaf). It then upserts rows (`Issued` or `Expired`, resolver, SANs, `InUse`, owning application), keeps `Pending` rows for TLS routes without a certificate, and removes rows that no route expects and that `acme.json` no longer holds. A certificate is in use when a routed host matches its main domain or a SAN; a wildcard covers one label. Operators can also run `POST .../certificates/sync`.
- **Expiring soon**: an in-use certificate that is still within 14 days of expiry (Traefik renews about 30 days before expiry) raises `certificate.expiring_soon` once per expiry through `INotificationEventPublisher`. The Vessel-side renewal state machine is gone; `RenewalDue`, `RenewalQueued` and `Revoked` are legacy status values that are no longer produced.
- **Delete / delete unused**: these remove entries from `acme.json`. Deleting does not revoke. Traefik keeps the certificate in memory, so the result reports `restartRequired` and the proxy must be restarted for the deletion to take effect.
- **Backups**: every write backs up the current file to `proxy/acme-backups/acme-{UTC timestamp}.json` (0600, directory 0700, not mounted into the proxy). The newest 10 are kept. Backups can be listed, restored (the current file is backed up first) and deleted. Restores refuse files that are not valid JSON. Writes are atomic with mode 0600.
- Key material, account keys and certificate bodies are never stored in the database, returned by the API, or quoted in errors. The former certificate/private-key secret reference columns are removed.

```text
GET    /api/v1/servers/{id}/certificates                           servers.read
POST   /api/v1/servers/{id}/certificates/sync                      servers.write
DELETE /api/v1/servers/{id}/certificates/{certificateId}           servers.write
POST   /api/v1/servers/{id}/certificates/delete-unused             servers.write
GET    /api/v1/servers/{id}/certificates/backups                   servers.read
POST   /api/v1/servers/{id}/certificates/backups/{name}/restore    servers.write
DELETE /api/v1/servers/{id}/certificates/backups/{name}            servers.write
```

Mutations on Local/DockerSocket servers require an instance administrator (`HostLocalExecutionGuard`), like other proxy changes. Issuance requests (`POST .../domains/{host}/certificates/issue`) still enqueue a `CertificateIssuanceJob` that applies the server's routes so Traefik requests the certificate.

## Configuration History and Dynamic Files (NET-07)

Upstream reference: branch `feat/proxy-config-history`, `app/Actions/Proxy/SaveProxyConfiguration.php`, `app/Livewire/Server/Proxy/DynamicConfigurations.php`, `app/Rules/ValidProxyConfigFilename.php`.

- **Encryption at rest**: `proxy_configuration_versions.Configuration` and `proxy_dynamic_configurations.Content` are protected with the secret key ring (`ISecretCipher.Protect`, purpose `proxy-configuration:{serverId}`). Legacy plaintext rows stay readable. Listing never returns text. `GET .../proxy-configurations/{versionId}/content` requires `servers.write` and is audited (`proxy_configuration.revealed`).
- **Source**: each version records `Generated`, `UserDynamic` (with `FileName`) or `Restore`. An apply whose routes hash matches the applied version re-delivers the file without adding a history entry.
- **Restore**: `POST .../proxy-configurations/{versionId}/restore` (`/rollback` is an alias) validates and delivers the old text as a new `Restore` version linked through `RestoredFromId`. History is never rewritten. The next generated apply (for example a deployment) supersedes a restored routes file.
- **Retention**: the daily `proxy.configuration-history-cleanup` job keeps the newest 20 versions per server plus the applied version of the generated routes and of each user file.
- **User dynamic configuration files** (`GET/PUT/DELETE .../proxy-configurations/dynamic/{fileName}`; reading and writing need `servers.write`, and host-local servers need an instance administrator): the file name must be a plain `*.yml`/`*.yaml` name of letters, digits, `.`, `-` and `_`, with no path separators, not hidden, and not in the reserved `vessel*` namespace. The content must parse as a single YAML mapping of `http`/`tcp`/`udp`/`tls` sections and must not contain private keys. Files are written next to `vessel-routes.yml` in `proxy/dynamic/`, where the file-provider watch picks them up.
